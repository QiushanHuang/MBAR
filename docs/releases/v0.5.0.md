# MBAR 0.5.0

More icon sources, native snapshots and a working permission recovery flow.
Released 2026-09-26 for **macOS 27 / Apple Silicon**.

[Download](https://github.com/QiushanHuang/MBAR/releases/tag/v0.5.0) ·
[English setup](../../README.md#install) · [中文](#中文)

## Changes from 0.4.0

MBAR can now find menu-icon candidates in ordinary image files, compiled `Assets.car`
catalogs and Electron ASAR archives. Existing verified adapters stay in place.
A unique high-confidence candidate is used automatically; otherwise the app's **图标…**
panel offers previews and a choice. It also supports imported images, template coloring,
restoring automatic matching and undoing the last saved choice.

Native capture reads a currently visible icon as it is drawn in the system menu bar.
It checks position stability and image quality, then asks you to preview and save the result.
MBAR never unfolds hidden items just to obtain an image. A saved snapshot has a capture
time and is invalidated after a target-app version change.

The permission fix addresses a specific failure: MBAR could say Screen Recording was
required even when its system toggle was on, because a negative preflight result stopped
the request. Explicit captures now go through ScreenCaptureKit's actual authorization path.
Failures expose **打开屏幕录制设置**, **重新检查并读取** and **重启 MBAR**; restart returns
to the same icon panel.

The app is **ad-hoc signed, without Developer ID signing or Apple notarization**.
There is no Intel build. Source and build scripts are tagged `v0.5.0`.

## Upgrade and permissions

1. Quit MBAR before replacing the app. Back up its preferences and
   `~/Library/Application Support/MBAR/` if you need a rollback.
2. Replace `/Applications/MBAR.app` and reopen it. Existing categories and user-selected
   images are retained. New apps still default to Visible.
3. If macOS rejects a previous permission after the signature changes, refresh only
   MBAR's entry for the current installed app, then reopen it.
4. For native capture, leave the target icon visible and use **读取当前原生图标**.
   Screen Recording is needed for this operation; reading app resources does not need it.

If you roll back to 0.4.0, restore its matching icon-data backup as well. Older builds do
not understand the new catalog/snapshot mapping records.

## Validation

Validation host: macOS 27.0 (26A428), Apple Silicon, Swift 6.4.

- Debug and Release: **67 automated tests passed** in each configuration. One opt-in
  live-capture test is normally skipped and was run separately with a visible target.
- Regression tests cover stale permission preflight, consent retry, error classification,
  relaunch arguments, catalog metadata and real catalog readback, ranking, persistence,
  late-result rejection and native crop quality.
- Installed-app GUI checks on the same capture implementation, before the release
  metadata bump, successfully previewed WeChat's template icon and AlDente's colored
  battery display. Existing saved choices were preserved; tests did not save new choices
  on the user's behalf.
- Release package checks cover version/build metadata (0.5.0/13), arm64 architecture,
  strict ad-hoc signature verification, ZIP extraction, DMG integrity and SHA-256 digests.

The local comparison of 20 running apps improved candidate coverage from **4 to 15**.
This does not mean 15 automatic matches or prove that every candidate reproduces the
current native state.

## Known limits

Saved resources and native snapshots are static. Battery numbers, speed labels and
charts in a snapshot do not update. Multi-item apps cannot yet be mapped individually.
Native capture needs a visible, stable target; no general cross-app API for retrieving
another app's live menu image has been established.

Hiding still relies on a private macOS interface and can affect system extras or the
clock/Notification Center. Use **显示全部（暂停）** to recover. Testing does not establish
all third-party menu actions, physical display arrangements, Spaces or sleep/wake behavior.

## 中文

**MBAR 0.5.0：扩展图标来源，加入原生快照，修复取图授权流程。**
2026-09-26，面向 macOS 27 / Apple Silicon。

### 相比 0.4.0

新增普通图片、`Assets.car` 图像资源库和 Electron ASAR 候选发现，同时保留已有专用适配。
唯一高可信候选会自动采用；有歧义时，在应用旁的 **图标…** 中预览并选择。
支持图片导入、模板着色、恢复自动匹配和撤销上次保存。

原生采集读取系统菜单栏中当前可见图标的实际画面。核对位置与图像质量后，先预览，再由你保存。
MBAR 不会为了取图展开隐藏项目。快照记录采集时间，目标应用版本改变后会要求重新采集。

本次权限修复解决了“系统录屏开关已开，应用仍直接提示无权限”的情况：旧预检值不再阻断用户请求，
改由 ScreenCaptureKit 判定实际授权。失败时提供 **打开屏幕录制设置**、**重新检查并读取** 和
**重启 MBAR**，重启后回到原图标面板。

### 下载与升级

- `MBAR-0.5.0-macos-arm64.dmg`：打开后拖入“应用程序”。
- `MBAR-0.5.0-macos-arm64.zip`：解压后移动 `MBAR.app`。
- `SHA256SUMS.txt`：两个安装包的校验值。

**ad-hoc 签名，未经 Developer ID 签名或 Apple 公证；未提供 Intel 版本。**
源码与构建脚本使用 `v0.5.0` 标签。

升级前退出 MBAR，需要回退时先备份偏好和 `~/Library/Application Support/MBAR/`。
替换 `/Applications/MBAR.app` 后重开，分类与手选图标会保留，新应用仍默认常驻。
签名变化后，若旧权限失效，只刷新当前 MBAR 的授权条目，再重开应用。

读取原生图标时保持目标可见，并允许录屏权限；资源读取不需要录屏。
回退到 0.4.0 时，也应恢复对应的图标数据备份，因为旧版不认识新增的来源记录。

### 验证与边界

验证环境：macOS 27.0（26A428）、Apple Silicon、Swift 6.4。

- Debug 和 Release 各 **67 项自动测试通过**；另一个实机采集测试默认跳过，已对可见目标单独运行。

  迟到结果隔离及原生裁切质量。
- 版本元数据升级前，同一采集实现的安装版 GUI 已成功预览微信单色图标和 AlDente 彩色电池图标。
  原手选图标保留，验证没有替用户保存新选择。
- 发行包检查涵盖版本/构建号 0.5.0/13、arm64、严格签名、ZIP 解压、DMG 完整性和 SHA-256。

同批 20 个运行中应用的候选覆盖从 **4 个增至 15 个**。这不是 15 个全部自动匹配成功的承诺。

没有通用验收结论。隐藏仍依赖私有接口，出现系统项目或时钟异常时，用 **显示全部（暂停）** 恢复。
